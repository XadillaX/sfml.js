# RmlUi 6.3 双向调用与完整帧性能验收

共享数值视图与 Core 默认数据视图保持了每帧固定跨语言调用，逐值写入、JS getter/transform 和自定义视图的调用随行数增长。当前矩形场景仍逐元素绘制；自定义实例的所有权维护仍线性扫描，逐元素 `setAttribute` 和监听器逐个注册路径有二次复杂度。100k 自定义 controller 场景超时，未取得帧分位数。性能验收仍有未通过项。

正式测量：数据 2026-11-16T06:55:34.046Z；字体 2026-11-16T06:55:41.021Z。主机 Apple M4 Max / Darwin 25.6.0 / arm64 / Node.js v22.22.2 / RmlUi 6.3。

33 个成功场景、1 个超时场景，成功场景的 84 组负载共 6,720 个完整帧计时样本。每组 20 帧预热、80 帧计时、5 帧独立分配/复制计数和 1 帧独立双向调用统计。p50/p95 使用 nearest rank，分别取排序后的第 40、76 个样本。所有原始样本和计数见 [JSON](frame-performance.json)，每组分位数、计数中位数/范围及内存快照见 [CSV](frame-performance.csv)。

## 测量口径

- 完整 CPU 帧依次包含 clear/flush、数据输入、dirty/model update、context update、render、display；各阶段独立计时。关闭 VSync。不使用 GPU fence/timer，display 可能等待 WindowServer。
- 计时时关闭 native 计数器、malloc logger 和 JS 入口包装。调用统计单独包装 RmlUi 与 SFML 的实际 addon 导出表，包含无 RuntimeBoundary 的值/字形接口。native-to-JS 记录已插桩的显式 V8 回调及类别；本次输入不含 Proxy 或 JS 属性访问器。
- `clear` 写入 SFML 共享命令；`flush` 与 `display` 各提交一次。文中的正向调用数包含这 2 次 SFML addon 提交。
- 数组数据场景为真实 1k/10k/100k 个 `i` 行，100 个 float64 数组根，每行高 1px、宽在 1/2/3px 间切换，视口 320×240。sparse 更新一个根，即 1% 行；all 更新全部行。每行属性和宽度在计时外进行 native 校验。
- `native` 是 C++ 直接填充相同 native backing，后续使用相同 Core 表达式、布局和渲染；它不是独立纯 C++ 程序的整帧基线。`native-scalar`、getter 和 transform 使用一个标量驱动相同输出，单独列出。
- 自定义 view 在 JS 读取共享数值并设置宽度，属性由 Core 默认 view 更新。controller 场景另注册每行 controller，并独立测量一次真实 click。`custom-attribute` 额外逐行调用 `setAttribute`，只实测 1k，未向 10k/100k 外推时间或分位数。
- 100k `custom-controller` 的完整子进程达到 300 秒超时。另一次限时 30 秒的诊断仍在 controller 初始化，最后保存的进度为 20k；这个数字是日志检查点，不能当作超时时精确注册总数，也不能据此断言初始化本身耗时至少 300 秒。超时记录及诊断原文保留在 JSON。
- 分配统计覆盖当前主线程的 macOS malloc-family 操作，包含 Core、Nan/V8 原生分配与图形驱动在该线程上的申请；不覆盖 V8 arena 内部对象、VM 分配、其他线程和 GPU 内存。诊断结束入口本身有成本，空操作对照单独保留；结果对象在关闭 logger 后创建。
- 复制字节仅覆盖数值 backing resize、SFML 几何去索引展开、owned glyph 快照和 effect scratch；未统计全引擎 memcpy。上传指成功 VBO update 和源纹理上传，不是驱动实际总线流量。绘制次数是 renderer 对 SFML target 的 draw 提交。
- `dataVariantFromJs` 只计 ReadOwnedDataVariant 入口；applyPatch 每路径还会执行通用 VariantFromJs，未计入这个 owned 指标。patch 的实际逐路径赋值数通过 scalarWrites 核验，不能把 owned 转换计数为 0 解释成没有类型转换。
