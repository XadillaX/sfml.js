RmlUi 렌더링과 Retina ​

RmlUi 레이아웃과 기하 데이터는 네이티브 백엔드에 유지됩니다. SFML이 정점 버퍼, 텍스처, 셰이더, 렌더 대상을 관리합니다. 런타임 전체 수명 동안 같은 열린 RenderWindow를 사용합니다.

렌더러 생성에는 SFML 셰이더 지원과 필수 프로그램 6개의 컴파일 성공이 필요합니다. 지원 또는 컴파일 실패는 등록·선택 전에 예외를 발생시킵니다. 기하나 클립 마스크 업로드 실패는 UI 프레임을 중단하고 호스트 뷰를 복원합니다. 병합 버퍼 할당만 실패하면 개별 그리기로 돌아가 제출 순서를 유지합니다.

프레임 합성 ​

창을 지우고 SFML 장면을 기록한 뒤 window.flush(), RmlUi 컨텍스트 렌더링, window.display() 순서로 실행합니다. flush는 UI 전에 장면 명령을 제출합니다. 렌더링 전 context.update()로 레이아웃, 애니메이션, 표시 밀도를 적용합니다.

context.render()는 투명한 UI 기본 레이어를 소유하며 렌더 순회가 성공한 뒤 호스트 장면에 합성합니다. 성공과 실패 모두 호스트 View와 어댑터 상태를 복원합니다. 콜백 예외는 현재 UI 프레임을 버립니다. 렌더 콜백에서 창을 읽으면 이미 제출된 호스트 장면이 보이며 UI 픽셀은 프레임 완료 후 창에 나타납니다.

컨텍스트 프레임과 오프스크린 레이어는 검증된 8비트 스텐실 버퍼를 소유합니다. 프레임 밖에서 RenderManager로 창에 직접 그릴 때는 settings.stencilBits: 8을 지정합니다.

레이어 0은 합성 소스와 대상 모두에 사용할 수 있으며 자체 합성과 알파 마스크 저장을 지원합니다. 컨텍스트 프레임 안에서는 RmlUi 내용만 포함하고 프레임 밖의 관리자 작업에서는 호스트 창을 나타냅니다. 예비 레이어는 크기가 같은 최대 8개를 32 MiB 저장 예산 안에서 유지하며 크기 변경 시 이전 크기의 레이어를 해제합니다.

물리 픽셀과 dp ​

macOS의 initialise(window)는 화면상 크기를 유지하면서 네이티브 Retina 표면을 활성화합니다. 이후 창 크기, 마우스／크기 변경 이벤트, 텍스처 캡처는 물리 픽셀을 사용합니다. 초기화 후 window.getSize()로 컨텍스트를 생성하세요.

밀도 2일 때결과
화면상 1024 × 768 창2048 × 1536 프레임버퍼와 컨텍스트
font-size: 20dp40 물리 픽셀, 겉보기 크기 유지
font-size: 20px20 물리 픽셀
마우스 입력배율을 다시 곱하지 않고 직접 전달

컨텍스트는 갱신 시 densityIndependentPixelRatio를 읽습니다. processEvent가 크기 변경을 처리합니다. context.dimensions는 캐시된 읽기 전용 뷰입니다. 네이티브 레이아웃 크기는 setDimensions(width, height)로 바꿉니다.

initialise(window, { highDpi: false })는 이미 활성화된 표면을 포함해 현재 상태를 유지합니다. 활성화한 표면은 shutdown() 이후에도 창을 닫을 때까지 유지됩니다. 다른 플랫폼은 백엔드가 보고하는 밀도를 사용하며 현재 값은 1입니다.

렌더러 지원 범위 ​

뷰포트, 시저, 소유 마스크, 행렬 제출과 저장·복원은 렌더 상태를 참고하세요.

기능현재 지원
텍스트, 텍스처, 단색 기하, 사각 클리핑구현됨
스텐실 클립 마스크와 둥근 overflow 클리핑구현됨, 스텐실 버퍼 필요
오프스크린 레이어와 합성SFML RenderTexture로 구현
블러와 드롭 섀도SFML Shader로 구현
레이어 알파 마스크 저장구현됨, 시저 영역의 원래 위치 유지
선형·방사형·원뿔·반복 그라데이션 및 creation모든 정지점과 동차 변환을 보존하는 네이티브 프로그램
CSS 이미지 마스크구현됨, macOS에서 전경／배경／마스크 조합을 GL3와 비교 검증
불투명도, 밝기, 대비, 반전, 회색조, 세피아, 색조 회전, 채도네이티브 사전 곱셈 색상 셰이더로 구현
배경 필터macOS에서 읽을 수 있는 UI 기본 레이어와 CSS 효과 조합 검증
지오메트리와 클립의 4×4 변환네이티브 동차 투영, Z 클리핑과 원근 보정 텍스처 보간

VisualTests 실행기는 상위 프로젝트 페이지 미리보기입니다. 충돌 없이 로드된다고 시각적 검증을 통과하거나 RmlUi 렌더러를 완전히 지원하는 것은 아닙니다.

색상 필터는 목록 순서대로 실행합니다. RenderManager.compileFilter(name, { value })의 네이티브 이름은 opacity, brightness, contrast, invert, grayscale, sepia, hue-rotate, saturate입니다. 색조 각도는 라디안이며 생략한 값은 1입니다. 명시한 값은 유한한 숫자여야 합니다. 행렬은 사전 곱셈 알파와 투명 픽셀을 유지하며 반전과 불투명도를 0–1로 제한합니다. 고정 GL3와 같이 행렬 출력은 RGBA8 채널 범위로 제한하며 원본 알파 값으로 제한하지 않습니다. 로드, 생성, 사전 로드 및 레이어 저장으로 얻은 일반 텍스처는 선형 필터링과 반복 주소를 사용하며 0–1 밖의 UV도 반복합니다. 효과 셰이더를 사용할 수 없으면 컴파일은 유효하지 않은 핸들을 반환합니다.

blur는 { sigma }를 사용하며 기본값은 1입니다. 유한한 음이 아닌 물리 픽셀 값이어야 합니다. 큰 반경은 고정 GL3의 단계별 절반 축소와 7점 가우스 커널을 사용한 뒤 2의 거듭제곱으로 안정적으로 배치합니다. 시저 영역 밖의 샘플은 투명하며, 축소 후 샘플이 남지 않는 영역도 투명하게 출력합니다.

drop-shadow는 { sigma, offset, color }를 사용합니다. sigma는 0, offset은 { x: 0, y: 0 }, 색상은 불투명 검정이 기본값입니다. 오프셋은 유한한 물리 픽셀 값이어야 하며 양의 Y는 아래쪽입니다. 색상은 사전 곱셈하지 않은 RGBA 바이트입니다. 원본 알파를 이동하고 착색한 뒤 필요한 경우 블러를 적용하며(sigma ≥ 0.5), 변경하지 않은 원본을 그림자 위에 합성합니다. 필터는 순서대로 처리하며 SFML 중간 타깃 3개를 재사용하여 사전 곱셈 픽셀과 원본 레이어를 유지합니다. macOS 네이티브 테스트는 홀수 크기의 전체／시저 이미지 16개를 공식 GL3와 비교하고 투명 경계, 원본 유지, 소수／음수 오프셋과 타깃 재사용도 검증합니다.

실제 RML/CSS 장면 10개로 전경 필터, 배경 필터, 그라데이션 마스크, 모든 조합과 변환된 둥근 모서리 클리핑을 검증합니다. macOS GL3/SFML 비교의 최대 RGB 채널 오차는 2 이하, 평균 오차는 0.1 이하를 요구합니다. 반복 프레임과 역순 렌더링은 동일한 픽셀을 유지하며 사전 곱셈 알파와 투명 모서리도 확인합니다. 네이티브 할당 검사 12개는 기본／추가 레이어, 중간 타깃, 캡처 실패와 재시도를 검증합니다. 마스크 레코드 할당이 실패해도 이미 캡처한 텍스처를 해제합니다. 전체 앱과 VisualTests 검증은 별도로 수행합니다.

지오메트리와 마스크는 전체 열 우선 행렬을 공유합니다. 이동은 행렬 변환보다 먼저 적용하며 왼쪽 위 물리 픽셀 투영과 −10000~10000 Z 범위를 사용합니다. 마스크는 정의 당시의 쓰기 시저와 변환을 보존합니다. 겹친 삼각형에도 논리적 교차를 유지하며 8비트 값이 소진되기 전에 정규화합니다. 사용자 vertex_shader는 지정한 정점 프로그램과 SFML 아핀 변환 규약을 유지합니다.

그라데이션과 creation 매개변수 ​

RenderManager.compileShader의 linear-gradient는 p0, p1, radial-gradient는 center와 양수 radius, conic-gradient는 center와 라디안 angle을 사용합니다. 로컬 픽셀 UV, 기본 false인 repeating, 태그가 있는 color_stop_list를 사용합니다. 위치는 유한하고 감소하지 않는 Unit.NUMBER이며 색상 바이트에는 알파가 이미 곱해져 있습니다. GL3의 순차 smoothstep으로 모든 정지점을 혼합하며 16개를 넘어도 보존합니다. 전체 목록을 GLSL에 넣고 GPU 컴파일이 실패하면 유효하지 않은 리소스를 반환합니다.

정지점이 하나면 단색입니다. 위치가 같으면 그 위치에서 뒤의 색상으로 전환합니다. 반복 범위는 처음과 마지막 위치 사이이며 길이가 0이면 마지막 색상입니다. 빈 목록, 감소하는 위치, 같은 선형 끝점, 양수가 아닌 반지름과 유한하지 않은 매개변수는 무효입니다. 원뿔 중심의 그라데이션 좌표는 0입니다.

creation은 shader 이름과 { value: 'creation', dimensions: { x, y } }를 사용하며 크기는 유한한 양수입니다. 정규화 로컬 UV와 SystemInterface의 경과 초로 고정 버전 GL3의 RGB 식과 정점 알파를 보존합니다. 중심 거리와 역수 분모의 하한은 1e-6입니다. 내장 효과는 전체 4×4 변환을 사용하고 선택적 텍스처를 무시합니다. 명시적 vertex_shader, fragment_shader는 사용자 GLSL 확장과 SFML 아핀 좌표 규약을 선택합니다.

밀도 검증 ​

packages/sfml.js-rmlui에서 npm test를 실행하고 macOS에서는 npm --prefix ../sfml.js-interop run test:high-dpi도 실행합니다. 1×／Retina 레이아웃, 글리프 래스터화, 적중 검사, 크기 변경, 물리 픽셀 캡처, 크기 제한을 검증합니다. 실제 모니터 사이의 창 이동은 장치 테스트가 필요합니다.
